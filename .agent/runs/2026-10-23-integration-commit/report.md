# Validated Engine integration

## 1. Goal and scope

Curate and review the validated integration, then commit it locally on main. The base is upstream `4905af9a566d66d3cd283dcb4f1032d9150110f3`. Push, release, dependency publication and installed-plugin updates are outside this authorization.

The route is preserve -> curate -> review -> validate -> local commit -> readback. Agent owns workflow definitions, task/session progress and bounded execution references. Runtime owns operation commit and transient-state reclamation. Authoring owns geometry, selections, source history and portable saves. Concrete storage, capture, recipes and production coordination remain optional host/provider code.

The integration retains upstream Code Authoring, language intelligence, compiler/toolchain support, optional IDE, Agent context/tool discovery and CLI. Generated catalogs, public exports, ownership, capability inventories, manifests and guide outputs accompany their source. The Editor controller prerequisite and completion tracker are retired; eight original contract records and 26 migration source files retain their exact hashes.

## 2. Review and verification

`source-review.json` records the final boundary, scope and credential-signature review. `validation.json` records final checks. `candidate-validation.json` retains the prior candidate's validation results and original evidence hashes without machine-specific paths. These are observed local checks, not hosted CI or device certification.

Of 2,494 packaged implementation files, 2,493 remain byte-identical to the distribution that passed real MCP, asset preparation, game building, IDE/browser and persistent authoring validation. The remaining file has one trailing ASCII space removed; all other bytes are unchanged. Syntax and generated-contract checks cover that formatting cleanup. Door, chest, a dense curved shell and an 870-node/162,240-triangle scene completed in one host. The fixed-scene 10,000-call run retained 167.26–167.32 MiB and zero Runtime journal/event backlog; archived receipt retrieval and restart recovery passed.

Raw logs, rendered evidence, old reports, rollback copies and checkpoints are retained locally outside source commits. `run.json` identifies the Engine task/session and its local workspace; checkpoint/object storage is deliberately excluded from commits. Restore that local state from preservation evidence when transferring machines. Validation reports establish correctness; task completion only records progress.

Fixed-scene endurance is not unlimited asset capacity. Live geometry, durable disk storage, history counts, materializing loads and non-streaming providers retain their documented limits. The controlled correction fixtures are engineering validation, not artistic or continuous-collision certification.

## 4. Integration boundary

One coherent local commit keeps source, exports, manifests and generated documentation consistent. The Git commit identifies the resulting source revision; local receipt state records its exact hash after commit. No publication or installed public Kit change is included. After a separately authorized Engine push/publication, update the canonical Kit pin and integrity and repeat consumer validation.
