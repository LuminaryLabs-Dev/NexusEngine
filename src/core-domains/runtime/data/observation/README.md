# Observation history

`createObservationHistoryKit` stores portable committed records in a Core ECS resource. Install Runtime Data first. Its `engine.n.observationHistory` API supports appendCommitted, getFrame, list, setRetention, snapshot/load and reset. Records require sessionId, nonnegative epoch/sourceFrame and committed:true. Duplicate retained identities with identical content are no-ops; conflicting or stale observations fail before mutation. Retention bounds both serialized UTF-8 bytes and record count. Oversized records fail rather than silently disappear. An evicted list cursor raises an error.

Active semantic state remains owned by its existing domains. Binary video/audio and provider save blobs remain external. Historical records may reference their content identities. Restoring history is not restoring a simulation or emulator.

Simulation's synchronous `registerCommitParticipant({id,prepare,apply,rollback})` API lets external observation Kits enlist domain snapshot changes in a commit. An optional synchronous afterCommit callback runs inside the same atomic transaction after the committed-frame/ledger resources are set; history publishers can capture the final resolution state there. Prepare must be pure and validate before mutation. Apply and rollback must be synchronous; asynchronous native work happens before the tick. The ECS transaction restores resource/component setter writes, entity allocation, event queues and journal entries. It does not deep-copy existing resource objects: callers must not mutate those in place. Closure-backed services must be restored by participant rollback. A failed rollback raises an aggregate error and requires explicit host recovery. Engine clocks and an already advanced external emulator are not rolled back; the host must stop the failed session.

Simulation snapshots now include resolution state, committed frame and revision ledger. Observer functions, policies and participant callbacks are runtime wiring and remain installed rather than serialized. Portable snapshots do not restore the host's native process or monotonic Nexus tick identity.
