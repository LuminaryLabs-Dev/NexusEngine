# Agent Decision and model-neutral steps

`n:agent:decision` owns portable versioned classification/judgment contracts, retained decisions and references to existing Agent proposals. It does not own HTTP, credentials, application labels, threshold policy or tool execution. `n:harness:routing` still resolves available authorized capabilities. An answered judgment is not execution authority or final validation.

Install `createAgentKit()` then `createAgentDecisionKit()` in the Engine. Use public imports from `nexusengine/domains/agent/decision` (also exported by the Agent entry). Create a request with ID, profile `{id,version,questions}`, state, binding `{goalRef,goalVersion,sourceRevision,evidenceRefs}` and permitted `proposalIds`. Questions use `choice/options`, `score/levels` or `probability`. `validateDecisionJudgment` checks identity/hash, matching bindings, typed answers, distributions and permitted selections. Results retain distinct `answered`, `uncertain`, `insufficient_evidence`, `unresolved`, `failed` and `budget_paused` states. Probabilities/confidence are optional and never invented for deterministic results. `resolveDecision` requires a current binding, existing proposal and explicit acceptance policy; hosts still authorize its route before dispatch.

Record a validated judgment with `engine.n.decision.record(request,result)`. Duplicate matching records reuse their retained value; changed content for an ID fails. Engine snapshot/restore retains decisions without invoking inference. Reset restores the configured baseline and does not touch external financial ledgers. Record capacity is bounded by maxRecords (default 1000).

`runAgentLoop` is the model-neutral name for `runSelfPropagation`. Existing `infer` callers remain supported. New callers provide `decide` instead, returning `{decision,usage:{modelCalls:0,tokens:0}}` for deterministic work, or reporting actual usage with awaited `accountUsage` callbacks. Never supply both infer and decide. No provider is selected or called by default. `validateDecision` is an optional caller-supplied gate before any execution. Existing execute and verify ports retain host authorization and authoritative receipt requirements.

For model calls, await `accountUsage({modelCalls:1})` before each attempt, then account actual tokens; providers/hosts retain monetary reservations. A callback may make zero, one or multiple attempts, including failed attempts. Return usage only if not already reported. Legacy infer without explicit usage conservatively counts one call, even when it throws. Model-call and token budgets can be zero for deterministic loops. Completion requires verifier proof and cannot exceed loop limits. Checkpoints during judgment are unresolved on restart and never re-inferred automatically. Pending operations require resolvePending with an authoritative receipt. Cancellation never erases provider usage or a retained execution receipt.

Inference classification requests use the existing neutral `input` envelope and declare the `classification` capability. Provider selection is still explicit, respects capacity and does not silently substitute protocols. A TypeSafe provider kit is optional; see kits/agent/loop-host/providers/README.md. Core has no Jev default, mandatory classifier review, universal 1000-token cap or Cloud policy.

Cloud is unchanged by this Engine update. Its future adapter must consume the public contracts and pin a validated Engine revision separately.

Graph-aware callers may add `graphRef` and nonnegative `graphRevision` to decision bindings. Both are required together. They participate in request identity and stale-selection rejection; existing bindings remain unchanged. Optional goal traversal uses the same decision/usage contracts: see [Agent Goal Graph](AGENT-GOAL-GRAPH.md).
