# 0.0.5 Render Device

`0.0.5` adds the provider-neutral Render device state package at
`n:render:device`. It records portable facts and exact-once receipts. It does
not create or execute a GPU device.

## Complete Import

```js
import { createEngine } from "nexusengine";
import { createRenderContractsDomain } from "nexusengine/domains/render/contracts";
import { createRenderLifecycleDomain } from "nexusengine/domains/render/lifecycle";
import { createRenderDeviceDomain } from "nexusengine/domains/render/device";

const engine = createEngine({
  kits: [
    ...createRenderContractsDomain(),
    ...createRenderLifecycleDomain(),
    ...createRenderDeviceDomain()
  ]
});
```

## Atomic Imports

| Capability | Public import | Ownership |
| --- | --- | --- |
| Device contract | `nexusengine/domains/render/device/contract` | Portable provider and device identity |
| Features | `nexusengine/domains/render/device/feature` | Feature declarations and negotiation |
| Limits | `nexusengine/domains/render/device/limit` | Numeric limit profiles and checks |
| Capabilities | `nexusengine/domains/render/device/capability` | Device, feature, and limit composition |
| Memory | `nexusengine/domains/render/device/memory` | Semantic budgets and reservations |
| Queue | `nexusengine/domains/render/device/queue` | Logical submissions and completion receipts |
| Lifecycle | `nexusengine/domains/render/device/lifecycle` | Device acquisition, readiness, loss, recovery, and release state |
| Loss | `nexusengine/domains/render/device/loss` | Loss incidents and resolution evidence |
| Diagnostics | `nexusengine/domains/render/device/diagnostics` | Read-only aggregate device reports |

## Provider Boundary

A provider creates the real device and returns portable acquisition and
readiness receipts. Core validates those receipts against the installed
provider and the declared capability profile. Memory reservations and queue
submissions are semantic records only; the provider performs real allocation,
command encoding, queue execution, and recovery.

Every mutation requires an `operationId`. Exact replay returns the original
receipt. Changed content under the same operation ID fails before mutation.
Queries and diagnostics do not mutate state.

There are no legacy Render Device imports, root forwarding exports, implicit
provider calls, backend-handle snapshots, or provider-object retention.
