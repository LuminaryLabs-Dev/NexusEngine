# 0.0.5 Render Lifecycle

`0.0.5` adds the provider-neutral Render composition lifecycle at
`n:render:lifecycle`. It does not replace Runtime lifecycle and it does not
execute a renderer.

## Complete Import

```js
import { createEngine } from "nexusengine";
import { createRenderContractsDomain } from "nexusengine/domains/render/contracts";
import { createRenderLifecycleDomain } from "nexusengine/domains/render/lifecycle";

const engine = createEngine({
  kits: [...createRenderContractsDomain(), ...createRenderLifecycleDomain()]
});
```

## Atomic Imports

| Capability | Public import | Ownership |
| --- | --- | --- |
| Installation | `nexusengine/domains/render/lifecycle/installation` | Selected provider identity and aggregate lifecycle phase |
| Startup | `nexusengine/domains/render/lifecycle/startup` | Startup request and readiness receipt |
| Shutdown | `nexusengine/domains/render/lifecycle/shutdown` | Shutdown request and completion receipt |
| Recovery | `nexusengine/domains/render/lifecycle/recovery` | Failed-provider recovery coordination and receipt |
| Reset | `nexusengine/domains/render/lifecycle/reset` | Atomic reset of composed lifecycle state |
| Snapshot | `nexusengine/domains/render/lifecycle/snapshot` | Portable capture and atomic restoration |

## Lifecycle

```js
engine.n.renderInstallation.install({
  operationId: "render:install:1",
  providerId: "my-render-provider",
  providerVersion: "1.0.0"
});

engine.n.renderStartup.begin({ operationId: "render:start:begin:1" });
engine.n.renderStartup.complete({
  operationId: "render:start:complete:1",
  providerReceipt: { providerId: "my-render-provider", ready: true }
});
```

Every mutation requires an `operationId`. Repeating the same command returns
the original receipt without replaying coordinated mutations. Reusing that ID
with changed content fails before mutation.

## Recovery

Recovery begins only from a failed installation. It first normalizes Startup
to idle, then records the recovery attempt. A completion receipt with
`ready: true` restores both Installation and Startup to ready. A receipt with
`ready: false` returns Installation to installed and requires a new Startup.
Failure leaves Installation failed. Any failed coordinated transition restores
all participating snapshots.

## Snapshot Boundary

Lifecycle snapshots contain only portable Installation, Startup, Shutdown,
Recovery, and Reset state. Provider objects, GPU handles, resources, compiled
shaders, surfaces, and frame state remain provider-owned. Restoring one invalid
component fails and rolls the complete lifecycle bundle back.

There are no legacy Render lifecycle imports, forwarding exports, implicit
provider calls, or snapshot coercions.
