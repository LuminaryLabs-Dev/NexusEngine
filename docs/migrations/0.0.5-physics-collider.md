# 0.0.5 Physics Collider

`0.0.5` proves `n:physics:collider` as the canonical owner of portable collider attachment, local pose, material binding, layer/mask/group filtering, sensor/trigger semantics, lifecycle, and exact-once registry records.

## Ownership

Own portable collider identity, attachment, filtering, sensor semantics, lifecycle, and exact-once records.

It owns:

- collider identity and attachment
- collider lifecycle state
- collider records and revisions
- collider-local pose and physical material references
- collision layers, masks, groups, and filters
- sensor and trigger descriptors

It does not own:

- collision detection or contact generation
- contact or constraint solving
- gameplay trigger consequences
- provider-native collider handles
- render geometry or GPU resources

## Atomic Kits

- `collider-attachment-kit`: Normalize a collider attachment to public Body and Shape registry identities.
- `collider-filter-kit`: Normalize provider-neutral collider layer, mask, group, and exclusion descriptors.
- `collision-group-kit`: Normalize a named collision layer-and-mask policy descriptor.
- `collider-identity-kit`: Normalize stable portable Physics collider identity, tags, and metadata.
- `collision-layer-kit`: Normalize one bounded provider-neutral collision layer.
- `collider-lifecycle-kit`: Normalize provider-neutral enabled and disabled collider lifecycle state and commands.
- `collision-mask-kit`: Normalize a deterministic bounded collision-layer set and its portable bit value.
- `collider-material-kit`: Normalize a collider reference to one public Physics material identity.
- `collider-pose-kit`: Normalize provider-neutral collider-local position and orientation descriptors.
- `collider-registry-kit`: Own portable collider records, revisions, reference validation, and exact-once mutations.
- `sensor-collider-kit`: Normalize non-solving sensor semantics independently from collision detection and event dispatch.
- `trigger-collider-kit`: Normalize event-selection semantics for a sensor-backed trigger collider.

## Proof

Direct behavior, lifecycle/composition where applicable, failure handling, portability, and backend-boundary behavior are exercised by `tests/core-domains/core-physics-collider-smoke.mjs`.

The Core records remain provider-neutral: concrete Rapier, PhysX, Three.js, WebGL, WebGPU, native-window, and GPU-resource handles stay outside this semantic boundary.
