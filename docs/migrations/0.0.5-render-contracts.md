# 0.0.5 Render Contract Foundation

`0.0.5` introduces the canonical backend-neutral render-execution boundary at
`n:render`. No previous canonical NexusEngine Render package path is retained
or forwarded.

Presentation remains authoritative for renderer-neutral visual meaning:
materials, lighting, cameras, UI, output policy, and semantic render-layer
graphs. Render Contracts validate the provider-facing records produced after
that meaning is resolved. They do not create GPU objects or execute a frame.

## Complete Import

```js
import { createEngine } from "nexusengine";
import { createRenderContractsDomain } from "nexusengine/domains/render/contracts";

const engine = createEngine({ kits: createRenderContractsDomain() });
```

## Atomic Imports

| Capability | Public import | Ownership |
| --- | --- | --- |
| Render Domain | `nexusengine/domains/render/contract` | Canonical execution identity and ownership boundary |
| Provider Contract | `nexusengine/domains/render/provider-contract` | Required and optional provider methods plus portable capabilities |
| Resource Schema | `nexusengine/domains/render/resource-schema` | Portable resource identity, lifetime, usage, dependencies, and source records |
| Frame Schema | `nexusengine/domains/render/frame-schema` | Ordered frame, view, pass, surface, and resource references |
| Pass Schema | `nexusengine/domains/render/pass-schema` | Resolved provider-facing pass references |
| Shader Schema | `nexusengine/domains/render/shader-schema` | Portable shader stages, entry points, bindings, source identity, and integrity |
| Event Schema | `nexusengine/domains/render/event-schema` | Ordered portable Render lifecycle and execution events |

## Provider Contract

A provider implements initialization, resource create/update/release, frame
begin, pass execution, frame submission, reset, and disposal. Snapshot,
restore, recovery, resizing, capture, and idle waiting are optional declared
methods. Validation inspects the object but never installs, invokes, or retains
it. Provider capability metadata must be JSON-portable.

## Record Rules

- Unknown fields fail rather than being silently retained.
- IDs are non-empty and list duplicates fail.
- Numeric values must be finite; counters and times cannot be negative.
- Objects must be plain, acyclic, and JSON-portable.
- Backend handles, functions, typed native objects, and provider instances are
  not transport records.
- Normalization returns a deep canonical copy and never mutates the caller.
- Schema Kits own no execution state beyond their repeat-stable lifecycle
  resource.

## Presentation Boundary

`render-layer-graph-kit` under `n:presentation:graphics` continues to validate
semantic layers, dependency order, and visual resource flow. A Render pass is
an already-resolved provider input. It accepts pass, frame, pipeline,
attachment, resource, command, viewport, and scissor references; it rejects
Presentation graph fields such as `requires` rather than silently assuming
graph ownership.

## Provider Boundary

- Host owns platform surface and lifecycle capabilities.
- Build owns Web, Android XR, PCVR, and OpenXR target packaging.
- Concrete WebGL, Three.js, headless, native, and OpenXR renderers remain
  provider Kits outside Core contracts.
- GPU resources, command encoders, compiled shaders, framebuffers, swapchains,
  and native handles remain provider-owned.

## Planned Duplicate

The source checklist also names `shader-schema-kit` under the later
`n:render:shader` capability group. This contract package is the canonical
owner of that Kit identity. The later row must reuse this atom, be renamed only
after proving a distinct atomic responsibility, or be dispositioned as a
duplicate. A second Kit with the same ID is forbidden.

There are no compatibility root exports, concrete providers, implicit package
installs, or old snapshot coercions.
