# 0.0.5 Physics Material Domain

`0.0.5` introduces the canonical provider-neutral physical material owner at
`n:physics:material`. No previous NexusEngine physical-material package path is
retained or forwarded.

Historical simple rigid-body and cube proofs embedded friction, restitution,
density-like mass assumptions, floor contact, integration, and product tuning
inside one object behavior. The new domain extracts only the universal physical
material semantics. Bodies, colliders, contacts, solving, visual presentation,
audio, and authored effects remain separate.

## Complete Import

```js
import { createEngine } from "nexusengine";
import { createPhysicsContractsDomain } from "nexusengine/domains/physics/contracts";
import { createPhysicsMaterialDomain } from "nexusengine/domains/physics/material";

const engine = createEngine({
  kits: [
    ...createPhysicsContractsDomain(),
    ...createPhysicsMaterialDomain()
  ]
});
```

## Atomic Imports

| Capability | Public import | Ownership |
| --- | --- | --- |
| Registry | `nexusengine/domains/physics/material/registry` | Immutable material identity and exact-once records |
| Friction | `nexusengine/domains/physics/material/friction` | Isotropic and anisotropic coefficients |
| Restitution | `nexusengine/domains/physics/material/restitution` | Bounded bounce coefficient and threshold |
| Density | `nexusengine/domains/physics/material/density` | Positive kilograms per cubic meter |
| Surface | `nexusengine/domains/physics/material/surface` | Physical type and portable tags |
| Combine Policy | `nexusengine/domains/physics/material/combine-policy` | Symmetric coefficient combination |

## Material Definition

```js
engine.n.physicsMaterial.defineMaterial({
  operationId: "material:define:steel",
  material: {
    id: "steel",
    friction: {
      staticCoefficient: 0.7,
      dynamicCoefficient: 0.5
    },
    restitution: {
      coefficient: 0.2,
      thresholdSpeed: 1
    },
    density: {
      kilogramsPerCubicMeter: 7850
    },
    surface: {
      surfaceType: "metal",
      tags: ["solid"]
    },
    combinePolicy: {
      frictionMode: "average",
      restitutionMode: "maximum",
      priority: 0
    }
  }
});
```

Material IDs are immutable. Exact operation replay returns the original
receipt. Reusing an operation ID with changed content or redefining a material
ID with different content fails before registry mutation.

## Pair Resolution

```js
const contactMaterial = engine.n.physicsMaterial.resolvePair("steel", "rubber");
```

Pair resolution is a read-only symmetric query. Available coefficient modes are
`average`, `minimum`, `multiply`, `maximum`, and `geometric-mean`. Explicit
policy priority wins first; equal priority uses canonical mode precedence and
stable material identity selection. A concrete provider consumes the resolved
record when it performs contact solving.

## Boundary Changes

- A physical surface is not a visual material.
- Shader, texture, decal, sound, particle, damage, and gameplay fields are not
  accepted by the physical material schemas.
- Density does not calculate body mass or inertia.
- Combine policy does not generate contacts or impulses.
- Native backend material handles do not enter Core state or snapshots.
