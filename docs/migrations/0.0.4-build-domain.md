# NexusEngine 0.0.4 Build Domain Cutover

`0.0.4` moves build behavior into the isolated `n:build` Domain. Projects no
longer own generated Rust workspaces, platform wrappers, target caches, or
Build receipts. They provide source and data only.

## Command Cutover

Use one command and repeated target flags:

```bash
nexusengine inspect ./project
nexusengine plan ./project --target web-live --target android-xr --target pcvr
nexusengine build ./project --target web-static --approve-plan <exact-plan-hash>
```

Target order and duplicates do not change the plan. Noninteractive execution
requires the exact reviewed hash. The output directory must be outside the
project, and Build verifies the project fingerprint before and after apply.

## Import Cutover

Build is not a root export:

```js
import { createBuildDomain } from "nexusengine/domains/build";
import { createOpenXrRuntimeKit } from "nexusengine/domains/build/target/openxr/openxr-runtime";
```

Application runtime Domains cannot import these surfaces. Build adapters may
inspect runtime manifests and public package entries, but Build never becomes
an installed application Kit.

## Legacy Native Source Audit

The canonical audit used `LuminaryLabs-Agents/NexusEngine-Rust` remote `main`
at `7c5d9fd11baf41c11020ea4f7fda2b4a3d050eda`. The existing local checkout was
not used as canonical evidence because it was behind the remote.

| Legacy source | `n:build` owner | Decision |
| --- | --- | --- |
| `nexus-project-compiler` | Analysis, IR, Rust Lowering | Preserve deterministic IR validation, stable Rust escaping, and generated-crate concepts. Full executable semantic parity remains a native release gate. |
| `nexus-packager` | Source, Isolated Stage, Artifact | Preserve source filtering, SHA-256 manifests, and staged output concepts. Reject arbitrary build-command shells, CSV targets, project-local output, and best-effort native success. |
| `nexus-openxr-host` | OpenXR Runtime | Preserve session-state and stereo-frame contracts. Do not claim it as an OpenXR implementation; the audited code is a plan/scaffold without loader or swapchain calls. |
| `nexus-xr-input` | OpenXR Input | Preserve normalized pose, action, and haptics boundaries. Product interaction behavior remains outside Build. |
| `nexus-render-gles` | OpenXR Render | Preserve stereo submission concepts only. Authored toon, outline, and sky behavior is presentation policy and is not imported into Build. |
| `nexus-android-bridge` | Android XR Target | Preserve generic lifecycle boundaries. Reject hardcoded app/game identity and scaffold status as native proof. |
| `nexus-host` and `nexus-host-ffi` | Runtime host owner outside Build | Do not move application runtime or sequence execution into Build. A target host may link only the generated Runtime ABI. |

The historical Builder repository is also not an implementation source for
`n:build`: it writes projects and runs broad agent workflows, violating the
read-only project and atomic ownership contracts.

## Target Status

- `web-live`: executable and browser proved.
- `web-static`: executable, self-contained, and browser proved.
- `android-xr`: deterministic plan only until SDK/NDK, Gradle/APK, OpenXR,
  generated runtime, device install, and headset proof pass.
- `pcvr`: deterministic plan only until Windows x64 compilation, packaging,
  OpenXR runtime, generated runtime, and headset proof pass.

A blocked target is not silently replaced. Successful sibling targets remain
cached, while the aggregate receipt stays failed until every requested target
succeeds.
