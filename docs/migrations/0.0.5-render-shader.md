# 0.0.5 Render Shader

`0.0.5` adds the provider-neutral Shader package at `n:render:shader`. It owns
portable Shader source lineage and execution records. It does not execute a
preprocessor, parser, compiler, linker, GPU driver, backend reflector, or
repair system.

## Complete Import

```js
import { createEngine } from "nexusengine";
import { createRenderContractsDomain } from "nexusengine/domains/render/contracts";
import { createRenderLifecycleDomain } from "nexusengine/domains/render/lifecycle";
import { createRenderDeviceDomain } from "nexusengine/domains/render/device";
import { createRenderResourceDomain } from "nexusengine/domains/render/resource";
import { createRenderShaderDomain } from "nexusengine/domains/render/shader";

const engine = createEngine({
  kits: [
    ...createRenderContractsDomain(),
    ...createRenderLifecycleDomain(),
    ...createRenderDeviceDomain(),
    ...createRenderResourceDomain(),
    ...createRenderShaderDomain()
  ]
});
```

## Atomic Imports

| Capability | Public import | Ownership |
| --- | --- | --- |
| Contract | `nexusengine/domains/render/shader/contract` | Stage vocabulary and provider boundary |
| Language | `nexusengine/domains/render/shader/language` | Portable source kinds, stages, and feature requirements |
| Source | `nexusengine/domains/render/shader/source` | Immutable text or binary revisions and integrity |
| Include | `nexusengine/domains/render/shader/include` | Acyclic include graph and deterministic closure order |
| Module | `nexusengine/domains/render/shader/module` | One stage, source revision, includes, and entry point |
| Program | `nexusengine/domains/render/shader/program` | Graphics, compute, or ray-tracing stage topology |
| Variant | `nexusengine/domains/render/shader/variant` | Exact defines, specializations, and feature requirements |
| Permutation | `nexusengine/domains/render/shader/permutation` | Bounded read-only variant expansion |
| Error | `nexusengine/domains/render/shader/error` | Portable diagnostics and source locations |
| Compile | `nexusengine/domains/render/shader/compile` | Logical request, success, and failure state |
| Reflection | `nexusengine/domains/render/shader/reflection` | Provider observations checked against the accepted program |
| Cache | `nexusengine/domains/render/shader/cache` | Compile-to-resident-Resource linkage and eviction selection |

The portable Shader interface remains at
`nexusengine/domains/render/shader-schema`. It is the existing canonical
`shader-schema-kit` under `n:render:contracts`; `n:render:shader` reuses it and
does not create a second schema owner.

## Execution Contract

Sources and includes are immutable revisions identified by deterministic keys
and SHA-256 content. Modules name exact source and include revisions. Programs
validate stage topology and the canonical Shader interface. Variants name one
exact define and specialization set. Permutations enumerate variants as a
read-only query and reject expansion above the declared bound or the Core hard
limit.

A compile request must name the exact program, optional variant, target
language, source closure hash, Device capability, queue, and pending queue
submission. Core derives the source closure from program, module, source, and
include hashes; a caller cannot substitute an arbitrary closure. Core checks
target stages and all required features before accepting the request.

The provider completes the queue submission and returns an explicit compile
receipt with exact device, provider, artifact, integrity, and binary-format
identity. Core records that receipt but never retains artifact bytes or a GPU
handle. Reflection is a separate provider observation and must cover the
declared interface. Cache entries point only to completed compiles and resident
Render Resources whose kind is `shader-program` and whose descriptor names the
same compile.

Every mutation requires an `operationId`. Exact replay returns the original
receipt, changed content under the same operation ID fails before mutation,
queries are read-only, snapshots are strict JSON-portable clones, and repeated
reset or load is stable. There are no root forwarding exports, legacy aliases,
implicit provider execution, or snapshot coercion.
